Paired single-cell RNA and ATAC, generated together

MultiFlow learns one coupled vector field for paired RNA and ATAC states. It generates paired profiles for a cell type and predicts paired responses to a perturbation in a cell type it has not seen, with the two modalities reading each other at every integration step.

Getting started

Installation

MultiFlow is a Python package built on PyTorch. The core package trains and samples the flow model; the optional paper extras add the encoders and decoders used to go from raw profiles to latent states and back.

Requirements#

Component Version Notes
Python 3.10, 3.11 or 3.12 Tested in continuous integration on all three.
PyTorch ≥ 2.1 Install the build that matches your CUDA driver first if you train on a GPU.
anndata, mudata, h5py anndata ≥ 0.9, mudata ≥ 0.2, h5py ≥ 3.8 Read and write paired H5MU files.
NumPy, pandas, SciPy NumPy ≥ 1.24, pandas ≥ 2.0, SciPy ≥ 1.10 Installed automatically.

The paper workflows were run on Linux with a CUDA GPU. The quick start runs on a CPU in seconds; full training on the paper datasets needs a GPU.

Three names The distribution is called multiflow-omics, the Python package multiflow_omics, and the command multiflow. The shorter name multiflow is taken on PyPI by an unrelated project. The command multiflow-omics also works, as an alias.

Getting started

Quick start

Train a small MultiFlow model on a synthetic paired file and generate new paired cells. Every command below was run on a laptop-class CPU; the whole page takes under a minute.

What this example is The toy file holds 48 paired cells of three cell types, with 4-dimensional latent states already stored in X_multiflow. It checks that the package works end to end. Real data start from raw profiles and go through the encoders first; see the tutorials.

Create and check a toy H5MU file#

shell
multiflow data example --output toy_multiflow.h5mu
multiflow data validate toy_multiflow.h5mu

validate prints a JSON report: the RNA counts are non-negative integers, ATAC is binary, the cells are paired, and the latent representations are present ("latent_ready": true).

Train#

shell
multiflow train --input toy_multiflow.h5mu --output runs/toy \
  --epochs 20 --batch-size 16 --hidden-dim 64 --device cpu

The paper uses a hidden width of 512 (the default). A width of 64 keeps this CPU run to a few seconds. The run directory runs/toy/ now holds model.pt, run.json and history.csv.

Generate paired cells for one cell type#

shell
multiflow generate --run runs/toy --output toy_generated.h5mu \
  --cell-type "B cell" --n 200 --device cpu

Cell types are given by name. An unknown name is rejected with the list of valid ones (here B cell, Monocyte, T cell).

Look at the result#

python
import mudata as md

generated = md.read_h5mu("toy_generated.h5mu")
print(generated["rna"].X.shape, generated["atac"].X.shape)   # (200, 4) (200, 4)
print(generated.uns["multiflow"]["ode_steps"])               # 100

The generated file holds paired latent states (rna.uns["matrix_scale"] == "latent") and, in uns["multiflow"], everything needed to reproduce them: the checkpoint hash, model configuration, seed, ODE steps, batch size and random-number mode. multiflow inspect --checkpoint runs/toy/model.pt prints the stored training settings.

The same in Python#

python
from multiflow_omics import (MultiFlow, TrainingConfig, fit, seed_everything,
                             sample_paired_latents, read_paired_latents,
                             save_checkpoint, load_checkpoint)

data = read_paired_latents("toy_multiflow.h5mu", condition_key="cell_type")

seed_everything(0)
model = MultiFlow(rna_dim=data.rna.shape[1], atac_dim=data.atac.shape[1],
                  num_classes=len(data.label_classes), hidden_dim=64)
result = fit(model, data.rna, data.atac, labels=data.labels,
             config=TrainingConfig(epochs=20, batch_size=16, device="cpu", reseed=False))
print(result.history[-1])          # {'epoch': 20.0, 'loss_rna': ..., 'loss_atac': ..., 'loss_total': ...}

b_cell = data.label_classes.index("B cell")
rna, atac = sample_paired_latents(result.model, 200, label=b_cell, steps=100,
                                  device="cpu", seed=0, standardizer=result.standardizer)

save_checkpoint("runs/api_model.pt", result.model, standardizer=result.standardizer,
                metadata={"label_classes": data.label_classes})
model, standardizer, metadata = load_checkpoint("runs/api_model.pt")

fit standardises each latent feature on the training cells and returns the fitted LatentStandardizer; pass it to sample_paired_latents so that samples come back on the original latent scale.

Tutorial 1

Cell-state generation

Train MultiFlow on the paired OpenProblems multiome data and generate paired RNA and ATAC profiles for a named cell type. This is the generation workflow of the paper, from the raw file to decoded profiles.

Before you start Install the paper workflow and run the commands from the root of the MultiFlow checkout. Training uses a CUDA GPU. The dataset is 8.38 GB.

raw paired H5MU ─► train/test split ─► RNA VAE + ATAC autoencoder ─► encode ─► MultiFlow ─► generate ─► decode

Download the OpenProblems data#

The paired dataset prepared by scDiffusion-X is pinned to one Figshare version (DOI 10.6084/m9.figshare.28582061.v3, CC BY 4.0). The downloader resumes interrupted transfers and checks size and MD5 before it writes the file.

shell
mkdir -p data
multiflow data download openproblem \
  --output data/openproblem_filtered.h5mu \
  --accept-license

Split before fitting anything#

Create the cell-type-stratified 80/20 split used by the benchmark. Split before training either encoder, so that test cells set neither encoder weights nor latent normalisation.

shell
python workflows/prepare_generation_data.py \
  --input data/openproblem_filtered.h5mu \
  --output-dir data/openproblem \
  --train-fraction 0.8 \
  --seed 20260717

This writes train.h5mu, test.h5mu, split_manifest.csv and split_metadata.json.

Train the RNA VAE#

RNA counts are normalised to 10,000 per cell and log1p-transformed inside the trainer. The VAE has three 1,024-unit layers and a 128-dimensional, L2-normalised latent state; its hidden layers start from the SCimilarity annotation model.

shell
curl -L "https://zenodo.org/records/8286452/files/annotation_model_v1.tar.gz?download=1" \
  -o external/annotation_model_v1.tar.gz
tar -xzf external/annotation_model_v1.tar.gz -C external

python workflows/train_rna_vae.py \
  --train-h5mu data/openproblem/train.h5mu \
  --scimilarity-model-dir external/annotation_model_v1 \
  --output-dir runs/openproblem/rna_vae \
  --max-steps 200000 --checkpoint-every 50000 \
  --batch-size 128 --seed 1234 --device cuda

The final checkpoint is runs/openproblem/rna_vae/rna_vae_step_199999.pt. If you select an earlier checkpoint, use a validation subset of the training split, never the test cells.

Train the ATAC autoencoder#

Generation uses the ATAC branch of a scDiffusion-X multimodal autoencoder: a 128-dimensional state and a Bernoulli decoder for binary accessibility.

shell
python workflows/train_multimodal_ae.py \
  --scdiffusion-x-root external/scDiffusion-X \
  --train-h5mu data/openproblem/train.h5mu \
  --output-dir runs/openproblem/multimodal_ae \
  --encoder-config workflows/encoder_multimodal_128.yaml \
  --dataset-name openproblem \
  --epochs 300 --seed 20260717

Encode the training cells#

One command runs both encoders and stores the two latent states in rna.obsm["X_multiflow"] and atac.obsm["X_multiflow"], together with the checkpoint hashes and encoder scale factors.

shell
multiflow paper encode \
  --task generation \
  --input data/openproblem/train.h5mu \
  --output data/openproblem/train_encoded.h5mu \
  --scdiffusion-x-root external/scDiffusion-X \
  --multimodal-ae-checkpoint runs/openproblem/multimodal_ae/checkpoints/final.ckpt \
  --encoder-config workflows/encoder_multimodal_128.yaml \
  --rna-vae-checkpoint runs/openproblem/rna_vae/rna_vae_step_199999.pt \
  --device cuda

Train MultiFlow#

shell
multiflow train \
  --input data/openproblem/train_encoded.h5mu \
  --output runs/openproblem/multiflow_generation \
  --model cell-state --condition-key cell_type \
  --epochs 1600 --batch-size 512 --learning-rate 1e-4 \
  --hidden-dim 512 --num-blocks 2 --cross-attention-dim 64 \
  --sampling-steps 100 --seed 0 --device cuda --hash-input

Latent means and standard deviations are estimated on the training cells, saved in model.pt and inverted automatically after sampling.

Generate and decode#

shell
multiflow generate \
  --run runs/openproblem/multiflow_generation \
  --output runs/openproblem/generated_cd4_latent.h5mu \
  --cell-type "CD4+ T activated" \
  --n 1000 --steps 100 --batch-size 512 --seed 0 --device cuda

multiflow paper decode \
  --task generation \
  --input runs/openproblem/generated_cd4_latent.h5mu \
  --reference data/openproblem/train_encoded.h5mu \
  --output runs/openproblem/generated_cd4_profiles.h5mu \
  --scdiffusion-x-root external/scDiffusion-X \
  --multimodal-ae-checkpoint runs/openproblem/multimodal_ae/checkpoints/final.ckpt \
  --encoder-config workflows/encoder_multimodal_128.yaml \
  --rna-vae-checkpoint runs/openproblem/rna_vae/rna_vae_step_199999.pt \
  --seed 0 --device cuda

Decoded RNA is a non-negative normalised log-expression reconstruction. Decoded ATAC is a Bernoulli sample, so it contains only 0 and 1.

Settings used in the paper#

Setting Value
RNA encoder 128-d RNA VAE, input normalised to 104 + log1p
ATAC encoder 128-d ATAC branch of the multimodal autoencoder, binary input
Flow width / residual blocks / cross-attention width 512 / 2 per stream / 64
Optimiser Adam, learning rate 10−4, batch size 512
Sampling midpoint ODE, 100 steps, batch size 512

Tutorial 2

Perturbation prediction

Predict the paired RNA and ATAC response to a knockout in a cell type the flow has never seen perturbed. The example holds out one cell type of the processed GSE274113 Perturb-multiome data, trains on the rest, then predicts and decodes one knockout in the held-out type.

Before you start Install the paper workflow. The processed dataset is 31.15 GB. The input needs rna.obs["perturbation"] with the non-targeting condition named control; it becomes perturbation index 0, an embedding fixed at zero.

Download and validate the data#

shell
multiflow data download gse274113 \
  --output data/GSE274113_filtered.h5mu \
  --accept-license

export PERTURBATION_H5MU=data/GSE274113_filtered.h5mu
multiflow data validate "$PERTURBATION_H5MU"

The fixed version is Zenodo 10.5281/zenodo.21986866; 10.5281/zenodo.21986865 stands for all versions. The source study is GSE274113. Review the record's terms before passing --accept-license.

Train and run the perturbation encoder#

Perturbation prediction does not use the generation RNA VAE. Both modalities are encoded by one scDiffusion-X multimodal autoencoder: RNA with a negative-binomial decoder on raw counts, ATAC with a Bernoulli decoder.

shell
python workflows/train_multimodal_ae.py \
  --scdiffusion-x-root external/scDiffusion-X \
  --train-h5mu "$PERTURBATION_H5MU" \
  --output-dir runs/perturbation/multimodal_ae \
  --encoder-config workflows/encoder_multimodal_128.yaml \
  --dataset-name GSE274113 --epochs 100 --seed 20260717

multiflow paper encode \
  --task perturbation \
  --input "$PERTURBATION_H5MU" \
  --output data/GSE274113_encoded.h5mu \
  --scdiffusion-x-root external/scDiffusion-X \
  --multimodal-ae-checkpoint runs/perturbation/multimodal_ae/checkpoints/final.ckpt \
  --encoder-config workflows/encoder_multimodal_128.yaml \
  --device cuda

Encoder and held-out cells The paper's leave-one-cell-type-out runs used one autoencoder fitted on all cells and applied the hold-out to flow training only. If the encoder should not see the held-out cell type either, build the raw fold first and retrain the autoencoder within each fold.

Build one leave-one-cell-type-out fold#

The example holds out basophilic erythroblasts and predicts the GATA1 knockout. GSE274113 covers ten cell types (BFU-E, CFU-E, MEP, pro-, basophilic, polychromatic and orthochromatic erythroblasts, megakaryocytes, EoBasoMast precursors, and monocyte/DC/granulocyte precursors) and 19 transcription-factor knockouts. Use the names exactly as they are stored in the file; md.read_h5mu(path, backed="r")["rna"].obs["cell_type"].unique() lists them.

All perturbed cells of the held-out type are removed from flow training; its control cells stay. Each cell type's context vector is the mean of its concatenated RNA and ATAC encoder states over the remaining training rows.

shell
multiflow paper prepare-perturbation-fold \
  --input data/GSE274113_encoded.h5mu \
  --output data/GSE274113_BasoE_fold.h5mu \
  --held-out-cell-type "Basophilic Erythroblast" \
  --condition-key cell_type \
  --perturbation-key perturbation \
  --control-perturbation control

Train the perturbation model#

shell
multiflow train \
  --input data/GSE274113_BasoE_fold.h5mu \
  --output runs/perturbation/BasoE \
  --model perturbation --condition-key cell_type \
  --perturbation-key perturbation --control-perturbation control \
  --epochs 600 --batch-size 512 --learning-rate 1e-4 \
  --hidden-dim 512 --num-blocks 2 --cross-attention-dim 64 \
  --sampling-steps 50 --seed 0 --device cuda

Predict, correct the mean, decode#

shell
multiflow generate \
  --run runs/perturbation/BasoE \
  --output runs/perturbation/BasoE_GATA1_latent_uncorrected.h5mu \
  --cell-type "Basophilic Erythroblast" --perturbation "GATA1" \
  --n 500 --steps 50 --batch-size 256 --seed 0 --device cuda

multiflow paper debias-perturbation \
  --input runs/perturbation/BasoE_GATA1_latent_uncorrected.h5mu \
  --training-fold data/GSE274113_BasoE_fold.h5mu \
  --output runs/perturbation/BasoE_GATA1_latent.h5mu \
  --held-out-cell-type "Basophilic Erythroblast" --perturbation "GATA1" \
  --condition-key cell_type --perturbation-key perturbation \
  --control-perturbation control --alpha 1

multiflow paper decode \
  --task perturbation \
  --input runs/perturbation/BasoE_GATA1_latent.h5mu \
  --reference data/GSE274113_BasoE_fold.h5mu \
  --output runs/perturbation/BasoE_GATA1_profiles.h5mu \
  --scdiffusion-x-root external/scDiffusion-X \
  --multimodal-ae-checkpoint runs/perturbation/multimodal_ae/checkpoints/final.ckpt \
  --encoder-config workflows/encoder_multimodal_128.yaml \
  --batch-size 2048 --seed 0 --device cuda

RNA is decoded as a raw-count expectation; ATAC is a binary Bernoulli output.

Evaluate the prediction#

To score the prediction, compare the predicted knockout effect with the real one in the held-out cell type. First produce the model's control cells for the same cell type, with the same three commands and --perturbation control, writing runs/perturbation/BasoE_control_profiles.h5mu. Then compare the mean effect on the genes with the largest real effect:

python
import numpy as np, mudata as md, scanpy as sc
from scipy import sparse

def log_profiles(adata):
    """Counts -> normalise to 10,000 per cell -> log1p, as a dense array."""
    a = adata.copy()
    sc.pp.normalize_total(a, target_sum=1e4)
    sc.pp.log1p(a)
    return a.X.toarray() if sparse.issparse(a.X) else np.asarray(a.X)

def effect_pcc(real_ko, real_ctrl, pred_ko, pred_ctrl, top=100):
    """Pearson r of the real and predicted effects (knockout mean - control mean)
    on the `top` genes with the largest real effect."""
    real = real_ko.mean(0) - real_ctrl.mean(0)
    pred = pred_ko.mean(0) - pred_ctrl.mean(0)
    genes = np.argsort(-np.abs(real))[:top]
    return float(np.corrcoef(real[genes], pred[genes])[0, 1])

real = md.read_h5mu("data/GSE274113_filtered.h5mu", backed="r")["rna"]
obs = real.obs
held = obs["cell_type"] == "Basophilic Erythroblast"
real_ko = real[held & (obs["perturbation"] == "GATA1")].to_memory()
real_ctrl = real[held & (obs["perturbation"] == "control")].to_memory()
pred_ko = md.read_h5mu("runs/perturbation/BasoE_GATA1_profiles.h5mu")["rna"]
pred_ctrl = md.read_h5mu("runs/perturbation/BasoE_control_profiles.h5mu")["rna"]

print(effect_pcc(log_profiles(real_ko), log_profiles(real_ctrl),
                 log_profiles(pred_ko), log_profiles(pred_ctrl)))

Both real and decoded RNA are on the raw-count scale, so they go through the same normalisation; the genes must be in the same order in both files. This is the idea of the effect PCC used in the paper; the paper's exact gene selection and settings are given in its Methods.

The training-only mean shift#

Before decoding, debias-perturbation moves the generated group to a target mean that is computed from training cells only. For each modality, with latent states z:

Δ = mean(z | perturbation p, training cells) − mean(z | control, training cells)
target = mean(z | control, held-out cell type) + α Δ
zgenerated ← zgenerated − mean(zgenerated) + target

The default --alpha 1 uses the full training effect. No perturbed cell of the held-out type is used. The settings are recorded in uns["multiflow_debias"] of the output.

ATAC encoder 128-d ATAC branch, binary input same

User guide

Data format

MultiFlow reads and writes paired cells as H5MU files: one MuData container with an rna and an atac modality. The package checks the pairing and the matrix scales and never guesses preprocessing.

The input you provide#

paired.h5mu
├── rna.X                        non-negative integer RNA counts
├── atac.X                       binary ATAC accessibility (0 or 1)
├── rna.obs["cell_type"]         cell-type name, no missing values
├── rna.obs["perturbation"]      perturbation input only; includes "control"
└── rna.obs_names == atac.obs_names   unique, same values in the same order

Audit any file before training:

shell
multiflow data validate paired.h5mu
multiflow data validate paired.h5mu --json report.json   # save the report

The report lists, for each matrix, its shape, range, whether it is finite, integer-like, non-negative and binary, and whether it meets the contract. latent_ready says whether the latent representations described below are present.

Latent representations#

The flow is trained on 128-dimensional encoder states, not on raw matrices. multiflow paper encode creates them and stores them in rna.obsm["X_multiflow"] and atac.obsm["X_multiflow"]. They are intermediate data; you are not expected to supply them by hand.

Task Modality Encoder Encoder input Decoder output
Generation RNA RNA VAE normalised 104 + log1p normalised log-expression
Generation ATAC multimodal AE, ATAC branch binary Bernoulli sample (0/1)
Perturbation RNA multimodal AE, RNA branch raw counts raw-count expectation
Perturbation ATAC multimodal AE, ATAC branch binary Bernoulli sample (0/1)

Use --rna-representation and --atac-representation to train on another obsm key. X can be chosen explicitly, but it is never used as a silent fallback when a latent key is missing.

Scales are stated, not guessed#

The RNA VAE and the multimodal autoencoder use different input and output scales, so an encoder release must state:

  1. the input matrix or layer and its scale;
  2. the feature identifiers, in exact order;
  3. checkpoint and configuration hashes;
  4. the latent dimension and the encoder's scale factors;
  5. the decoder's output scale; and
  6. whether the encoder was trained on the training split only.

On top of the encoder, MultiFlow fits a feature-wise latent standardiser on the training cells. The standardiser and the mapping from names to integer labels are stored in model.pt and run.json.

Perturbation inputs#

  • The perturbation column (default perturbation) must contain the control condition (default control). It is reserved as index 0 and contributes an exactly zero perturbation embedding.
  • The context matrix is stored in uns["multiflow_context_matrix"], with its row names in uns["multiflow_context_classes"]. The names must match the cell-type classes in the same order; MultiFlow rejects missing or reordered rows. multiflow paper prepare-perturbation-fold writes both.

Generated files#

multiflow generate writes paired latent states to rna.X and atac.X, marked uns["matrix_scale"] = "latent", and records in mdata.uns["multiflow"]:

Key Content
checkpoint_sha256 hash of the model file that produced the cells
model_config model type and sizes
seed, ode_steps, batch_size, rng_mode everything that determines the random draws
label_classes, perturbation_classes the name ↔ index mappings
standardization_inverted whether the latent standardiser was undone

multiflow paper decode then turns the latent states into profiles with the exact checkpoint bundle used to encode the training data. A decoder must never be taken from an unrelated file.

User guide

Models

MultiFlow is a flow-matching model on paired latent states. One network predicts two velocities, one for RNA and one for ATAC, and the two streams exchange information through bidirectional cross-attention, so the modalities are integrated as one coupled system.

Three architectures#

Name Class Command option Use
MultiFlow CellStateFlow --model cell-state (default) Generate cells of a named cell type.
MultiFlowPerturbation PerturbationFlow --model perturbation Predict the response to a perturbation in a cell context.
MultiFlowConcat ConditionalConcatFlow --model concat Concatenation ablation, kept to reproduce the benchmark.

The vector field#

  • Each stream is projected to a hidden width of 512 and passes through two residual blocks, a middle block and two more residual blocks, with skip connections between them. The same residual blocks process both streams.
  • Every residual block is modulated by the condition, the sum of a sinusoidal time embedding and the label embedding, through a scale and a shift.
  • Three cross-flow modules (CFM1–CFM3) couple the streams. In each one, RNA queries attend to ATAC keys and values, and ATAC queries attend to RNA keys and values.

Feature-level cross-attention#

Each modality enters a cross-flow module as a single token whose channels are its 512 hidden features. Attention is computed between features, not between cells or sequence positions:

AR←A = softmax( qR kA⊤ / √64 ),   hR ← hR + WR AR←A vA
AA←R = softmax( qA kR⊤ / √64 ),   hA ← hA + WA AA←R vR

Here every hidden feature gets a 64-dimensional query, key and value. Each attention matrix is therefore 512 × 512, one row per feature of one modality and one column per feature of the other. The Attention Explorer shows these maps for CFM2.

Conditioning#

  • Cell state. num_classes cell types, each with a learned embedding added to the time embedding.
  • Perturbation. A context embedding and a perturbation embedding replace the class embedding. The context embedding is taken from a fixed matrix, by default the mean encoder state of each cell type (frozen during training, freeze_context=True); its width must equal the hidden width or half of it. Perturbation index 0 is the control; its embedding is exactly zero and receives no gradient. Time, context and perturbation embeddings are each layer-normalised before they are added.

The flow objective#

For a target paired state x1 = (x1R, x1A), MultiFlow draws one Gaussian source over the concatenated RNA–ATAC space and a time t uniformly from (0, 1), and regresses the velocity of the straight path between them:

x0 = (x0R, x0A) ~ N(0, IdR+dA),   xt = (1 − t) x0 + t x1,   vt = x1 − x0
loss = ‖ v̂R(xt, t, c) − vtR ‖² + ‖ v̂A(xt, t, c) − vtA ‖²

The RNA and ATAC blocks of the source are independent coordinates of one full-rank random variable. Their dependence at the end point is learned by the coupled vector field, not imposed by the source. The concatenation ablation keeps its historical shared source only to reproduce the benchmark.

Choosing sizes#

Parameter Default Paper Effect
hidden_dim 512 512 width of each stream; also the size of the attention maps
num_blocks 2 2 residual blocks before and after the middle block
cross_attention_dim 64 64 query/key/value width per feature
num_layers (concat only) 8 — depth of the concatenation network

Feature-level attention costs grow with the square of hidden_dim; sampling the default model on a CPU is slow, so use a GPU for real data or a smaller width for tests.

Training and sampling

How MultiFlow fits the vector field, how it integrates it to produce cells, and which settings decide whether a result can be reproduced exactly.

Training#

Each epoch shuffles the paired cells and, for every mini-batch, draws a joint Gaussian source and a flow time per cell, builds the straight-line state and regresses its velocity (objective). The optimiser is Adam. The loss history is returned by fit and written to history.csv by the command line.

TrainingConfig field Default Meaning
epochs 600 passes over the training cells
batch_size 512 cells per optimisation step
learning_rate 1e-4 Adam step size
seed 0 seed of the training stream
device cuda if available, else cpu where training runs
standardize True standardise each latent feature on the training cells
noise_mode auto source distribution; auto picks the one the model requires
reseed True fit reseeds before training; the CLI seeds once before building the model and sets this to False

Latent standardisation#

With standardize=True, fit estimates a mean and a standard deviation for every RNA and ATAC latent feature on the training cells and trains on the standardised values. The fitted LatentStandardizer is returned in TrainingResult.standardizer, saved in the checkpoint, and inverted after sampling. It sits on top of the encoder's own scaling and does not replace it.

Seeds#

For an exact rerun through the Python API, call seed_everything(seed) before building the model, so that the initial weights are reproducible as well. The command line does this for you.

Sampling#

sample_paired_latents integrates the learned vector field from the Gaussian source at t = 0 to t = 1 with the explicit midpoint rule. At each step the RNA and ATAC velocities are evaluated together, so each modality's update depends on the other's current state.

Setting Generation Perturbation
ODE steps (steps, --steps) 100 50
batch size 512 256

The command line takes the step count saved with the run (--sampling-steps at training time) unless --steps is given, and records the value in the output.

Random-number modes#

rng_mode What it does When to use it
joint (default) draws one full-rank Gaussian over the concatenated RNA–ATAC space per batch and splits it into the two blocks all new work
batch_invariant draws the whole initial state first, so a seed gives the same cells for any batch size comparing runs with different batch sizes; uses memory proportional to the number of cells
legacy_interleaved reproduces the historical two-call RNA/ATAC draw order reproducing archived results only

Record the seed, batch size, number of steps, device and package version with every result: together they determine the sampled cells. Generated H5MU files store all of them.

Perturbation prediction#

For the perturbation model, give the cell context and the perturbation by name (--cell-type, --perturbation) or by index (label, perturbation). The control, index 0, has a zero perturbation embedding, so sampling with the control gives the model's control cells for that context. The paper then applies the training-only mean shift before decoding.

Outputs and reproducibility

Every run writes its model together with the settings and hashes needed to reproduce it. This page lists what is written where, and what to keep.

The run directory#

multiflow train --output runs/name creates a new directory:

File Content
model.pt portable checkpoint: model configuration and weights, latent standardiser, optimiser state, epoch, loss history and metadata

prints the stored metadata without loading the data.

Checkpoints#

  • save_checkpoint writes atomically, so an interrupted save never leaves a half-written file.
  • load_checkpoint rebuilds the model from its stored configuration and returns (model, standardizer, metadata). It loads with PyTorch's safe weights-only loader.
  • Checkpoints from the original research scripts use other layouts. Convert a trusted one once with multiflow migrate or migrate_legacy_checkpoint; pass --trust-source only for a file whose origin you have checked, because it allows PyTorch's unrestricted loader.
shell
multiflow migrate --source old_model.pt --output model.pt \
  --model-type perturbation \
  --standardizer-npz latent_stats.npz \
  --label-classes "BFU-E" "CFU-E" "Pro-E" \
  --perturbation-classes control GATA1 TAL1

Reproducibility checklist#

Keep these with every result; run.json and the H5MU metadata already record most of them.

  1. Checksum of the raw H5MU and the split manifest.
  2. Exact feature order and matrix scales.
  3. Encoder configuration, checkpoint hashes and scDiffusion-X scale factors.
  4. Flow latent statistics (the standardiser) and the label mappings.
  5. Training settings and sampling settings: seed, batch size, ODE steps, device, random-number mode, package version.

Never swap a decoder A decoder is only valid for the encoder that produced the training latents. Do not exchange a decoder checkpoint after the flow has been trained.

User guide

FAQ and troubleshooting

Answers to the questions and error messages that come up most often, and a short glossary of the terms used in these pages.

Running#

Sampling on a CPU is very slow#

Each cross-flow module computes a 512 × 512 attention matrix for every cell at every integration step, so a full-size model needs a GPU for real data. To check an installation on a CPU, train a small model with --hidden-dim 64, as in the quick start, and generate a few hundred cells.

I run out of GPU memory#

Lower --batch-size for training or generation. The cells are integrated batch by batch, so a smaller batch only takes longer. With --rng-mode batch_invariant the whole initial state is drawn at once, which uses memory in proportion to the number of cells; use the default joint mode for large runs.

"unknown cell-type … choose from […]"#

Cell types and perturbations are given by name, exactly as they were spelled in the training file. The error lists the valid names; they are also stored in run.json (label_classes, perturbation_classes) and printed by multiflow inspect --checkpoint runs/name/model.pt.

Data#

validate reports contract_ok: false#

The input must hold raw, paired profiles:

  • rna.X with non-negative integer counts, not normalised values;
  • atac.X with only 0 and 1; binarise a count matrix first;
  • the same cells in the same order in both modalities (obs_names identical).

The report names the matrix and the property that failed (finite, integer-like, non-negative or binary).

latent_ready: false#

The file has no latent representations yet. Run multiflow paper encode (see the tutorials), or point train to existing keys with --rna-representation and --atac-representation. MultiFlow never falls back to X silently.

Can I use my own encoder?#

Yes. Store the paired latent states in rna.obsm and atac.obsm under any key and pass the keys to train. MultiFlow does not guess preprocessing, so keep the encoder's scale factors and decode the generated latents with the decoder that belongs to the same encoder.

A dataset download stopped halfway#

Run the same multiflow data download command again: it resumes the transfer and checks the size and MD5 before it writes the final file. --force starts again from scratch.

Results#

How do I reproduce a result exactly?#

Keep the seed, batch size, number of ODE steps, device, random-number mode and package version. Generated files store all of them in uns["multiflow"]. Use --rng-mode batch_invariant if you need the same cells for different batch sizes. See Outputs and reproducibility.

Why does the perturbation workflow shift the generated mean?#

For a cell type the flow has never seen perturbed, the paper corrects the mean of the generated group with the perturbation effect estimated on the training cells. No perturbed cell of the held-out type is used. The formula is on the perturbation tutorial.

I have checkpoints from the original research scripts#

Convert each trusted file once with multiflow migrate (or migrate_legacy_checkpoint in Python), giving the label and perturbation names in order. See Checkpoints.

Attention Explorer

An interactive page for the cross-attention of trained MultiFlow models. It shows the 512 × 512 attention map of the second cross-flow module and turns strong pairs of hidden elements into candidate peak–gene links, with gene tracks, GO terms and regulatory networks.

Open the Attention Explorer

What it shows#

  • Attention map. Rows are the 512 ATAC hidden elements (A0–A511) and columns the 512 RNA hidden elements (R0–R511). Each square is the cross-attention of one pair in CFM2 at flow time t = 0.90, averaged over cells. Click a square to select the pair and zoom in.
  • Peak–gene links. Gradient attribution gives each ATAC element a ranked list of peaks and each RNA element a ranked list of genes. A selected pair proposes a link wherever one of its peaks lies within 120 kb of the TSS of one of its genes; links are marked TSS, Promoter or by distance.
  • Gene track. The locus around a link, with reference tracks: H3K27ac for the OpenProblems cell types; ChIP-seq of the perturbed factor, GATA1 and TAL1, and GATA1 HiChIP loops for the Perturb-multiome contexts.
  • Elements and GO. The top genes and peaks of each element and the GO programs enriched among its genes.
  • Regulatory network. The strongest routes from peaks through ATAC and RNA elements to genes, for the current map.

Contexts tagged held-out cell type were left out of training. Each map can be shared by copying the page address. A built-in tutorial (top right of the explorer) and a guided example walk through one finding step by step.

Reading the links The peak–gene links are candidates proposed by the model's attention. They are a starting point for follow-up with independent data such as ChIP-seq or chromatin contacts, not validated regulatory interactions.

Release notes#

Version 0.1.0 (alpha):

  • Source-layout Python package for paired latent flow matching, with the cell-state, perturbation and concatenation models.
  • Feature-wise latent standardisation, midpoint ODE sampling, portable checkpoints and the multiflow command line.
  • The canonical source is one full-rank joint Gaussian over the concatenated RNA–ATAC latent space; the historical draw order remains available as rng_mode="legacy_interleaved".
  • Paired H5MU training and output contracts, with cell-type names kept in checkpoints.
  • Version-pinned, checksum-verified downloads of both tutorial datasets.
  • End-to-end paper workflows: RNA VAE and multimodal autoencoder training, encoding raw profiles, leave-one-cell-type-out folds, the training-only mean shift and decoding.
  • Default sampling steps match the paper: 100 for cell-state generation and 50 for perturbation prediction.
